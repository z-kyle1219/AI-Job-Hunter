## 三、字段与核验口径

每条岗位包含：**岗位名称、企业、城市、岗位要求、原始链接、来源名称、抓取时间、核验状态**，另加岗位类型、届别、学历、薪资、方向标签、对口专业、备注。

- **核验状态**：`在招` = 详情页按钮为「立即申请」且投递时间未过期；`已停招` = 页面显示「已结束」；显示「当前岗位已下线」或「待上线」的一律剔除，不入库。
- **岗位要求**：从 JD 原文提炼 2–4 句，保留技术栈、届别、专业限制与加分项；完整原文点「原始链接」。
- **核验方式**：每条链接均由抓取程序实际打开详情页读取，非搜索引擎摘要拼接；另对 5 条做人工二次抽检（华为通用软件、卓望全栈、北森 AI 算法、百川智能实习、字节 AI 全栈实习），字段与原文一致。
- **去重规则**：同一企业同一岗位多次发布（如北森后端 469522/470122）只保留一条，另一条在备注注明。

## 五、已知局限

1. **来源单一**：本版岗位详情均来自牛客网职位页（企业官方校招信息在平台的同步发布）。已尝试字节/腾讯/小米官网与实习僧，页面为前端渲染、无法稳定抓取正文，故未纳入；下一版应补企业官网与高校就业网两类源。
2. **样本偏互联网/企业服务**：央国企（银行金融科技、运营商）、科研院所、外企在华研发中心尚未覆盖，而这恰是北大生源的重要去向。
3. **时效性强**：部分岗位投递窗口只有 2–4 周，10 条已停招的岗位保留是为了留下"岗位画像"，使用前务必点原始链接确认。
4. **学历字段个别不一致**：如锐捷「AI 算法工程师」页头标硕士、正文写本科及以上，已在学历列与备注注明。

## 六、扩张到"中国全专业"的路线

**阶段一（本版，已完成）**：北大 × 计算机/软件/AI/数据 × 北京 × 技术岗，验证字段结构、核验流程与去重规则，单轮 20–50 条。

**阶段二（1–2 个月）：北大全专业 + 北京**
- 建"专业 → 岗位族"映射表（本版 Excel「专业对照」sheet 已给出骨架）：金融/经管 → 券商基金研究、银行管培、金融科技、商业分析；法学 → 律所实习、企业法务、数据合规；医学/生物 → 医疗 AI、临床研究、药企；人文/外语/新闻 → 内容运营、国际化、市场品牌。
- 每专业先做 20 条种子岗位，复用同一套 14 字段 + 核验状态，保证跨专业可比。
- 城市仍限北京，降低抓取与核验成本。

**阶段三（3–6 个月）：全国 + 多源**
- 城市扩到北上广深杭蓉宁汉西等 10–15 个，按"城市 × 专业 × 岗位族"建索引。
- 源扩到：企业官网校招页、高校就业网、招聘平台、政府/事业单位公告；每源一个抓取模板（列表页 → 详情页 → 字段映射），失败自动降级。
- 工程机制：T+1 失效巡检（重访链接、比对按钮状态）、企业/岗位指纹去重、人工抽检 10%、字段缺失率监控。

**规模化关键取舍**：宁可"每天 200 条高可信"也不要"一次 2 万条脏数据"。真实性与可追溯（原始链接 + 抓取时间 + 核验状态）是这个产品相对招聘平台的唯一差异化。

## 七、复现与更新

```bash
python build_jobs.py     # 读取 jobs/batch_*.json，输出 xlsx + md
```

新增数据只需按同样字段追加 JSON 到 `batch_*.json`，脚本会自动去重（同企业 + 同岗位名）、归一公司名（如"北京字节跳动科技有限公司"→"字节跳动"）、按"在招优先、校招优先"排序。
